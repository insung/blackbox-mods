# blackbox-mods

[English](README.md)

Claude 가 무엇을 보고, 무엇을 정하고, 어디서 일했는지를 대화 옆 패널 하나에 기록하는 Claude Code mod 다.

`/blackbox-mods` 로 연다. 패널은 이 명령으로만 열린다. 닫혀 있는 동안에도 기록은 계속 쌓이고, 열면 보인다. 패널에는 탭 여섯 개가 있다.

| 탭 | 보이는 것 |
| --- | --- |
| 세션 로그 | 요청마다 색 있는 요청 시각 `[14:02]` 과 그 아래 요청 요약 제목(Markdown `##`. 데스크톱은 큰 제목, 터미널은 굵은 글씨)이 있다. 그 아래에 DB 쿼리(목적, SQL, 결과 표), Claude 가 읽은 파일(목적, 전체 경로, 결론), Edit·Write·NotebookEdit 로 바꾼 파일(작성·수정, 전체 경로), 그 밖의 Bash 명령(Bash description 으로 적은 목적, 앞 8줄까지 bash 로 강조한 명령, 출력 앞 5줄, 실패·거부 표시)가 시간순으로 쌓인다. 항목마다 종류(파일 읽기·파일 수정·명령·쿼리)를 색 있는 머리줄로 보인다. 머리줄에 시각은 없다. 목적·실행·결과는 `- 목적:` 같은 Markdown 목록으로 보이고, 명령과 결과는 목록 아래 코드 블록으로 보인다. 요청 묶음은 한 번에 하나씩 보이며 `◀ Prev`·`Next ▶` 로 넘긴다. 사이의 `현재 / 전체` 는 요청 묶음 수이고, 마지막 묶음을 보는 중이면 새 요청을 따라간다 |
| 결정 사항 | 사용자가 정할 항목(`[ ]`)과 Claude 가 스스로 정한 항목(`[x] … (Claude 가 정함)`)을 요청별로 묶어 세션 로그와 같이 `[요청 시각]` 과 요청 요약 머리 아래에 보인다. 정해지면 같은 줄에 `=> 결과` 와 `-> 사용자 답변` 이 붙는다. 선택지 버튼을 누르면 프롬프트 창에 `d1: 선택지` 가 채워진다. 보내기는 사용자가 한다 |
| Git | 이 세션에서 처리한 이슈와 PR 을 저장소별로 묶어 `▸ owner/repo  N건` 머리줄 아래에 보인다(저장소와 항목은 대화에 처음 나온 순서). 처리한 것은 `gh issue/pr` 의 쓰기 동작(생성, 코멘트, 닫기, 머지 등. `view`·`list`·`status`·`diff`·`checks` 는 뺀다)이 닿았거나 이 세션 커밋이 이어진 이슈·PR 이다. 각 줄은 앱의 PR 표시와 같은 순서다: 상태 · #번호 · 브랜치 · +추가 −삭제 · CI. 이 세션에서 Bash 로 만든 커밋(짧은 SHA · 제목, `-q` 로 출력이 없던 커밋은 git 에서 제목으로 찾는다)은 커밋한 폴더의 `origin` 저장소를 기록하고, 같은 저장소에서 메시지의 `#N` 이나 PR 의 head 브랜치로 그 이슈·PR 아래에 잇는다. 잇지 못한 커밋은 그 저장소 묶음의 「이슈 없는 커밋」 에, `origin` 을 모르는 커밋은 「▸ 저장소 모름」 에 둔다. 프롬프트·답변·`gh … view`·`gh` 출력에서 언급만 한 이슈·PR 은 맨 아래 「참고한 이슈·PR」 에 저장소별로 상태 · #번호 · 제목과, 프롬프트·답변에서 나왔으면 그 출처(`사용자 프롬프트`, `Claude 답변`)만 보인다. `gh` 명령 이름과 명령 결과는 출처로 보이지 않는다. 데스크톱 앱에서 #번호를 누르면 프롬프트 창에 「내장 브라우저로 <URL> 열어줘」 가 채워진다(쓰던 글이 있으면 그 뒤 줄). 보내면 Claude 가 앱 내장 브라우저에 그 이슈·PR 을 연다. 모드가 내장 브라우저를 직접 부르면 auto mode 가 거부하기 때문이다. 터미널에서는 일반 링크다 |
| 워크 트리 | 이 세션이 쓰는 git 워크트리를 저장소별 트리로 보인다. 사용 중인 워크트리에는 「VS Code 로 열기」 버튼이 있다 |
| 스킬 사용량 | 스킬 실행을 플러그인, 커스텀 스킬, 내장 스킬 묶음별 횟수와 비율로 보이고, 실행을 일으킨 요청을 발췌한다 |
| 암묵적 합의 | 아무도 묻지 않았지만 Claude 가 전제로 삼은 것(범위, 용어, 작업 방식, 요청 해석 등)을 종류와 근거와 함께 요청별로, 오래된 것부터 시간순으로 보인다. 요청 묶음 머리는 세션 로그와 같다. 추정 항목(`[?]`) 줄을 누르면 고르고(`▶` 표시) 다시 누르면 푼다. `선택 맞음`·`선택 아님` 을 누르면 프롬프트 창에 고른 항목을 쉼표로 이은 `a1, a3: 맞음` 또는 `a1, a3: 아님` 이 채워지고 고른 것이 풀린다. `선택 해제` 는 고른 것만 푼다. 보내기는 사용자가 한다. 확인된 항목은 `[o]`, 철회된 항목은 `[-]` 와 바뀐 내용을 보인다 |

## 설치

mod(hooks 모듈)를 지원하는 Claude Code 가 필요하다. Claude Code 2.1.295 에서 확인했다.

```bash
claude plugin marketplace add insung/blackbox-mods
```

```bash
claude plugin install blackbox-mods@blackbox-mods
```

이미 열린 세션에서는 `/reload-plugins` 를 실행한 뒤 `/blackbox-mods` 를 실행한다.

새 버전이 올라오면 아래로 갱신한다.

```bash
claude plugin update blackbox-mods@blackbox-mods
```

## Claude 에 더하는 것

패널을 채우기 위해, 모델이 부를 도구 네 개를 등록하고 시스템 프롬프트에 규칙을 넣는다.

| 도구 | 쓰임 |
| --- | --- |
| `mcp__blackbox-mods__track_decisions` | 사용자가 정할 항목과 Claude 가 정한 항목, 그리고 각 항목이 어떻게 정해졌는지를 기록한다 |
| `mcp__blackbox-mods__track_agreements` | Claude 가 묻지 않고 전제로 삼은 합의와 그 근거, 사용자가 확인했는지 철회했는지를 기록한다 |
| `mcp__blackbox-mods__note_reads` | 파일을 왜 읽었고 읽고 무엇을 알았는지 기록한다 |

시스템 프롬프트 규칙:

- SQL 문장마다 맨 앞에 `-- 조회 목적: <목적>` 주석을 붙인다. 패널은 이 주석을 쿼리 목적으로 보인다.
- 결정 항목은 `track_decisions` 로 등록하고, 사용자가 답하면 갱신한다. `d1: 선택지` 형식의 답은 `d1` 항목의 답이다.
- 묻지 않고 전제로 삼은 합의는 `track_agreements` 로 등록한다. 묻고 답한 항목은 등록하지 않는다. `a1: 맞음` 은 `a1` 을 확인, `a1: 아님` 은 철회하는 답이다. `a1, a3: 맞음` 처럼 여러 id 를 쉼표로 이으면 각 id 에 같은 답을 한 것이다. 철회되면 Claude 가 그 전제로 한 작업을 다시 확인한다.
- 파일을 읽고 결론을 냈으면 `note_reads` 로 목적과 결론을 보낸다.

도구를 부르지 않아도 자동으로 기록되는 것: `run_query.py` 나 `mysql` 을 실행한 Bash 명령, Read 도구로 읽은 파일, `AskUserQuestion` 답, 스킬 실행, 대화에 나온 GitHub 참조.

## 기록 보관

패널 기록은 디스크에도 남는다. 데스크톱 앱이 15분 동안 쓰지 않은 세션의 프로세스를 멈추거나, Claude Code 를 재시작해도 같은 세션을 다시 열면 이전 기록이 그대로 보인다.

- 저장 위치: Claude Code 의 `$.store`. Claude Code 설정 디렉터리(기본 `~/.claude/`) 아래에 있는 이 플러그인 전용 JSON 파일이다. 세션마다 `session:<세션 id>` 키 하나에 기록과 마지막 저장 시각(`updatedAt`)을 둔다.
- 저장 시점: 기록이 바뀌고 1초 뒤, 턴이 끝날 때, 세션이 끝날 때.
- 복원: 세션이 시작될 때 같은 세션 id 의 기록을 읽어 패널에 되돌린다. 새 세션은 빈 패널로 시작한다. 다른 세션의 기록은 읽지 않는다.
- 저장하는 것: 세션 로그(요청, 쿼리, 명령·파일, 읽은 파일), 결정 사항, 암묵적 합의, 워크 트리가 쓰는 작업 위치, 마지막 사용자 요청, 보던 탭과 페이지. Git, 워크 트리, 스킬 사용량 탭은 세션이 시작될 때 대화 기록과 git 에서 다시 읽으므로 저장하지 않는다.

보관 규칙은 플러그인 코드가 세션이 시작될 때와 저장할 때마다 스스로 지킨다. 따로 실행할 스크립트는 없다.

| 규칙 | 내용 |
| --- | --- |
| 30일 보관 | 마지막 저장 뒤 30일이 지난 다른 세션의 기록을 지운다 |
| 전체 4 MiB | `$.store` 는 플러그인마다 JSON 4 MiB 까지만 받는다. 모든 세션 기록의 합계가 한도에서 여유 256 KiB 를 뺀 값(3.75 MiB)을 넘으면, 마지막 저장이 가장 오래된 다른 세션부터 하나씩 지운다. 합계가 그 아래가 되면 멈춘다. 전체를 지우지 않는다 |
| 현재 세션 | 현재 세션 기록은 지우지 않는다. 현재 세션 하나만으로 한도를 넘으면 저장할 사본에서 쿼리·명령 결과처럼 큰 글을 잘라 저장하고(`… (저장 한도를 넘어 잘림)`), 그래도 넘으면 오래된 세션 로그 항목부터 뺀다. 결정 사항과 암묵적 합의는 남긴다. 패널에 보이는 기록은 줄이지 않는다 |

저장이 실패해도 패널은 그대로 동작한다. 실패한 변경은 다음 저장 때 다시 쓴다.

## 설정

| 항목 | 기본값 | 뜻 |
| --- | --- | --- |
| `githubUser` | 빈 값 | 이슈와 PR 상태를 읽을 gh 계정(`gh auth token --user <값>`). 비우면 gh 기본 계정을 쓴다 |

`/plugin configure blackbox-mods@blackbox-mods` 로 정하거나, 설치할 때 `--config githubUser=<계정>` 을 붙인다.

## 알려진 한계

- 쿼리 판정과 조회 목적 규칙은 한 팀의 DB 도구(`run_query.py`, `mysql`)에 맞춰져 있다. 다른 도구의 쿼리는 아직 기록하지 않는다.
- 기록은 세션마다 따로 쌓인다. 세션끼리 공유하지 않는다.
- 이 기능이 들어가기 전에 사라진 기록은 되돌릴 수 없다.
- mod 가 로드되기 전에 보낸 요청은 요약이 없어서 「(요청 기록 없음)」 으로 묶인다.

## 개발

```bash
claude plugin validate .
```

```bash
npx -p typescript tsc -p .
```

```bash
claude plugin test .
```

`tsconfig.json` 은 `.claude-plugin/types/tsconfig.json` 을 상속한다. 이 파일은 Claude Code 가 mod 를 로드할 때 만든다. 그래서 `tsc` 를 실행하기 전에 mod 를 한 번 로드해야 한다(예: `claude --plugin-dir .`). MCP 도구 타입은 일부러 뺐다. 이 목록은 컴퓨터마다 다르고, 크면 타입 검사가 한도를 넘는다.

설치한 플러그인은 설치할 때 만든 복사본을 실행한다. 그래서 폴더를 고쳐도 설치본에는 반영되지 않는다. 고친 내용을 바로 보려면 설치본을 끄고, 폴더를 hot reload 하는 세션에서 로드한다: `claude --plugin-dir <폴더>`, 또는 세션의 mods 폴더(`~/.claude/dev-mods/<세션 id>/`).
